# 个人 Blog 第一版前端设计规格

日期：2026-07-12

## 1. 产品目标

第一版不是后台系统，也不是全部功能的空壳集合，而是一套可真实浏览的个人品牌前台。访客应在 30 秒内理解站点主人是谁、擅长什么、做过哪些项目，并能继续阅读文章、查看成长动态或打开简历。

长期目标保持不变：逐步演进为个人官网、作品集、博客、在线简历、内容管理、数据分析和 AI 助手的统一平台。

## 2. 第一版范围

本阶段实现以下公开页面：

1. 首页：个人定位、技术方向、代表项目、最新文章、近期动态和行动入口。
2. 作品集：项目筛选、项目卡片与状态展示。
3. 项目详情：问题背景、解决方案、技术栈、职责、成果、截图和外部链接。
4. 文章列表：分类、标签、摘要、阅读信息与搜索入口的视觉形态。
5. 文章详情：正文排版、目录、代码块、引用、图片和上一篇/下一篇导航。
6. 动态时间线：以简短内容呈现学习、开发、比赛和阶段进展。
7. 关于我：个人经历、能力结构、成长路径和联系方式。
8. 在线简历：高密度、可打印的履历页面与 PDF 下载入口。

本阶段不实现登录、后台 CRUD、数据库、真实搜索、评论、留言、统计、在线状态检测、文件上传、AI 或真实多语言。所有内容由类型化模拟数据驱动。

## 3. 视觉方向

主题采用蓝白渐变，但不使用大面积高饱和霓虹。白色和极浅蓝承担阅读背景，深蓝承担文字层级，亮蓝只用于行动按钮、链接、状态和局部光晕。

视觉关键词：清澈、可信、克制、年轻、技术感。

- 页面背景：白色到极浅蓝的纵向渐变，并叠加低对比度网格或柔和光斑。
- 主色：深海军蓝；强调色：科技蓝；辅助色：天蓝。
- 卡片：白色半透明表面、细蓝灰边框、轻阴影，不依赖夸张玻璃拟态。
- 字体：中文优先使用系统无衬线字体，英文与数字保持清晰、紧凑。
- 圆角：中等圆角形成统一语言；按钮、标签、卡片共享有限的圆角层级。
- 动效：首屏淡入、卡片轻微抬升、数字和标签渐显；尊重 reduced-motion 设置。

深色模式不在第一版范围，但颜色令牌必须避免把主题值散落在组件中。

## 4. 信息架构

全局导航保持单层：主页、作品、文章、动态、关于、简历。移动端折叠为抽屉菜单。右侧保留一个主要行动按钮“查看简历”。

首页遵循单向叙事：

```text
身份与定位
  -> 核心能力
  -> 代表项目
  -> 最新文章
  -> 近期动态
  -> 联系与简历
```

首页与“快速了解我”不重复建设。第一版把三分钟速览能力直接融入首页；以后有真实招聘投放需求时，再根据访问数据决定是否增加独立页面。

## 5. 前端架构

采用 Next.js App Router、React、TypeScript 和 Tailwind CSS 4。页面默认使用服务端组件，只有筛选、移动导航和必要动效使用客户端组件。

建议模块边界：

```text
src/
├── app/          路由、布局、元数据与页面组合
├── components/   跨页面 UI 与业务展示组件
├── content/      第一版类型化模拟内容
├── features/     projects、articles、timeline、resume 领域组件
├── lib/          格式化、路由和通用纯函数
├── styles/       全局样式与设计令牌
└── types/        稳定的内容模型与公共类型
```

组件只消费结构化数据，不直接拥有大段业务文案。未来接入 API 时替换数据提供层，不重写展示组件。

## 6. 核心组件

- `SiteHeader`：桌面导航、移动导航和简历入口。
- `Hero`：身份、定位、核心行动和社交链接。
- `SectionHeading`：统一标题、说明和可选跳转。
- `ProjectCard`：项目封面、技术栈、状态和链接。
- `ArticleCard`：文章元信息、摘要、分类和标签。
- `TimelineItem`：动态类型、时间、正文和媒体摘要。
- `TechBadge`：有限颜色规则下的技术标签。
- `StatusBadge`：在线、开发中、维护中、已归档四种语义状态。
- `ResumeSection`：复用的简历章节容器。
- `SiteFooter`：联系入口、社交链接和版权信息。

项目、文章、动态分别保持独立内容模型，不创建一个塞满可选字段的万能内容类型。

## 7. 数据流与未来接口

第一版数据流为：类型化内容文件 -> 服务端页面 -> 展示组件。筛选状态只保留在对应客户端组件中，不建立全局状态仓库。

后续接入 FastAPI 后，页面通过生成的 TypeScript API Client 获取数据；服务端组件负责初始读取，客户端查询只用于交互刷新。公开内容以稳定 slug 作为 URL 身份，不把数据库 ID 暴露为页面地址。

## 8. 多语言边界

第一版只提供中文，不安装 i18next，不出现语言切换按钮。

未来采用 i18next 与 react-i18next，并将路由演进为 `/zh-CN/...` 和 `/en/...`。界面文案按 `common`、`home`、`projects`、`articles`、`resume` 命名空间拆分；文章、项目和简历的多语言内容由后端保存语言版本，不能只翻译 UI 而忽略业务内容。

当前实现必须避免：用中文文本作为程序判断条件、拼接文案生成布局、在通用组件内部硬编码页面段落。

## 9. 错误与空状态

- 无项目或无文章时显示明确空状态，不留下空白区域。
- 图片加载失败时使用与主题一致的占位表面和文本替代。
- 无效 slug 返回清晰的 404 页面，并提供返回作品或文章列表的入口。
- 外部链接使用安全属性并明确标识跳转。
- 模拟数据缺少非必要字段时由组件自然降级，不为每个字段堆叠分支。

## 10. 响应式与可访问性

以手机、平板、桌面三个内容断点验证，不以具体设备型号驱动设计。正文保持合适行宽；项目卡片从单列自然扩展；简历在窄屏改为纵向信息流。

页面必须具备语义标题层级、键盘可达导航、可见焦点、足够颜色对比度、图片替代文本和 reduced-motion 支持。蓝色不能成为传递状态的唯一手段。

## 11. 测试策略

- Vitest：内容格式化、筛选和状态映射等纯逻辑。
- Testing Library：导航、项目筛选、移动菜单和空状态。
- Playwright：首页主路径、作品到详情、文章到详情、简历入口及移动端导航。
- Lighthouse：性能、SEO、可访问性和最佳实践基线。

第一版不为静态展示快照堆积低价值测试，优先覆盖用户能感知的行为。

## 12. 验收标准

1. 八类公开页面均可通过导航或内容链接抵达。
2. 首页在首屏明确显示身份、方向、代表能力和主要行动。
3. 蓝白渐变主题在全站一致，正文阅读区域保持高对比度。
4. 作品、文章和动态均由类型化模拟数据驱动。
5. 手机端不存在横向滚动、菜单遮挡或卡片内容溢出。
6. 404、空内容和图片失败具有可理解的降级表现。
7. 页面具备基础 SEO 元数据和稳定语义结构。
8. 当前不包含 i18next 运行时代码，但内容与组件边界允许后续接入。
9. 构建、类型检查、静态检查与核心端到端路径全部通过。

## 13. 明确延后

后台管理、身份认证、富文本编辑、真实文件上传、评论与留言、站内搜索、访客统计、项目点击统计、在线状态检测、定时备份、AI 摘要、AI 项目文案、AI 简历问答以及多语言运行时全部延后。它们仍在长期路线图中，但不允许削弱第一版公开前台的完成度。
